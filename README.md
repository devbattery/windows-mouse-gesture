# Glide for Windows

크롬 확장 **Glide**의 우클릭 마우스 제스처를 모든 Windows 10/11 앱에서 쓰기 위한 상주 프로그램입니다.

> **현재 단계: M1 프로토타입.** 성능과 우클릭 호환성을 검증하는 단계라 콘솔에서 실행되고,
> 실행하는 제스처는 `←`(뒤로 가기) 하나뿐입니다. 설정 화면·궤적 표시·앱별 예외는 M2 이후에 들어갑니다.

## 동작 방식

- 오른쪽 버튼을 누른 채 그리면 방향(←→↑↓, 최대 12획)을 인식합니다. 인식 규칙은 확장과 같습니다.
- 그냥 우클릭하면 원래 우클릭(컨텍스트 메뉴)이 그대로 동작합니다.
- **Shift·Ctrl·Alt·Win**을 누른 채 우클릭하면 제스처 없이 원래 우클릭이 됩니다.
- 움직이지 않고 **길게 누르고 있으면**(기본 400ms) 원래 우클릭으로 넘겨줍니다. 탐색기의 우클릭 드래그(복사/이동 메뉴)처럼 우클릭 드래그가 필요할 때 씁니다.
- 제스처 중 **Esc**를 누르면 취소합니다(Esc는 앱에도 전달됩니다).
- 펜·터치 입력과 다른 프로그램이 보낸 입력은 건드리지 않습니다.

## 요구 사항

- Windows 10 22H2 또는 Windows 11 (x64)
- Rust 1.85 이상 (`stable-x86_64-pc-windows-msvc`)
- Visual Studio 2022 Build Tools의 C++ 빌드 도구와 Windows SDK

## 빌드와 실행

```powershell
cargo build --release
.\target\release\glide-core.exe
```

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `--threshold <12~48>` | 22 | 방향 판정 거리(96 DPI 기준 px). 모니터 배율에 맞춰 자동 환산 |
| `--hold-ms <100~3000>` | 400 | 움직이지 않고 누르고 있으면 원래 우클릭으로 넘기는 시간 |
| `--stats-sec <초>` | 30 | 훅 처리 시간 통계 출력 주기(0이면 종료할 때만) |

`Ctrl+C`로 종료하면 마지막 통계를 출력합니다.

## 검사

```powershell
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
```

`tests/gesture_fixtures.rs`는 확장의 `shared.js`로 만든 `fixtures/gestures.json`과 결과를 비교해,
두 구현이 같은 입력에 같은 제스처를 인식하는지 확인합니다. 확장의 인식 규칙이 바뀌면 다시 생성합니다.

```powershell
node tools/gen-gesture-fixtures.cjs <확장 저장소>/shared.js
```

## M1 검증 절차

M1은 아래 게이트를 통과해야 본 개발(M2)로 넘어갑니다. 수치는 목표값입니다.

- [ ] 훅 처리 시간 p99 1ms 미만, 1ms 이상 0회에 가깝게 (콘솔 `[통계]` 줄)
- [ ] 모든 CPU 코어에 부하를 건 상태로 10분 뒤에도 제스처 동작, `재설치` 횟수 증가 확인
- [ ] 대기 중 CPU 0~0.1%, 메모리(작업 집합) 20MB 이하 (작업 관리자)
- [ ] 단순 우클릭의 컨텍스트 메뉴가 정상: 탐색기, 바탕화면, 메모장, VS Code, Office (앱 5종)
- [ ] 탐색기 우클릭 드래그가 길게 누르기로 동작
- [ ] 비활성 창 위에서 시작한 `←` 제스처가 그 창에서 실행되거나, 실행하지 않고 안내됨
- [ ] 배율이 다른 모니터(100%·150% 등)에서 같은 체감으로 인식

콘솔 로그에는 대상 앱의 실행 파일 이름(예: `notepad.exe`)이 함께 찍혀 앱별 결과를 기록할 수 있습니다.

## 구조

```
src/
  gesture.rs   방향 인식기 (확장 shared.js의 Gesture 이식, 무할당)
  machine.rs   우클릭 상태 머신 (삼킬지·통과시킬지 결정, 순수 로직)
  stats.rs     훅 처리 시간 히스토그램 (원자적 카운터)
  win/
    hook.rs    WH_MOUSE_LL 훅 스레드 (판단만 하고 바로 반환)
    worker.rs  입력 재전송·동작 실행·로그
    input.rs   SendInput (주입 입력에 표식을 달아 훅이 다시 잡지 않게 함)
    clock.rs   QueryPerformanceCounter
    mod.rs     명령줄·스레드 시작·종료 처리
tests/         확장과의 인식 결과 비교
fixtures/      확장 코드로 생성한 인식 픽스처
tools/         픽스처 생성 스크립트 (Node)
```

## 알려진 제한 (M1)

- 관리자 권한으로 실행된 창(작업 관리자 등) 위에서는 동작하지 않습니다. M3에서 uiAccess 서명으로 해결할 예정입니다.
- 앱별 예외가 없어서 **크롬 계열 브라우저에서도 이 프로그램이 우클릭을 가로챕니다.** M1을 실행하는 동안에는 Glide 확장 대신 이 프로그램의 `←`만 동작합니다. M2에서 브라우저를 기본 예외로 둘 예정입니다.
- 실행 중에는 Windows가 서명되지 않은 실행 파일 경고(SmartScreen)를 띄울 수 있습니다.
- 오른쪽 버튼을 누른 채 판정 전에 다른 버튼을 누르면(로커 제스처), 앱은 다른 버튼 누름을 먼저 받고 오른쪽 누름을 나중에 받습니다. 로커 제스처는 M1 범위가 아닙니다.

## 개인정보

- 네트워크 통신을 하지 않습니다.
- 키보드 훅을 설치하지 않습니다. Esc는 제스처 중에만 키 상태를 조회합니다.
- 로그는 콘솔에만 출력하고 파일로 남기지 않습니다. 창 제목은 읽지 않고, 실행 파일 이름만 표시합니다.

정하지 않았습니다(공개 배포 단계에서 결정).
